# Tsuzuri（綴）

日本語 | [English](README.en.md)

動く要素（クイズ・計算・グラフ・タブ・手順・折りたたみ・画像の比較・用語の説明・記事どうしのリンク）を埋め込める記事ツール。独自ドメインで動く独立したサイトとして公開できる。

- 読む人：`/`（記事一覧）と `/<記事のURL>`。ページはサーバーでHTMLにして返すので、検索エンジンやSNSのプレビューが本文を読める
- 書く人：`/write`。自分のアカウントでログインして書く。行の先頭で `/` を押すと部品を選べる

デモ：https://tsuzuri-omega.vercel.app

## 特徴

- **覚えることは3つ**：書く／行頭の `/` で部品を選ぶ／公開する
- **動く記事**：クイズ・計算（スライダーつき）・棒グラフ・タブ・手順・折りたたみ・画像の比較・用語の吹き出し
- **検索とSNSに強い**：記事はサーバーでHTMLにして返す。OGP・構造化データ・サイトマップ・RSS つき
- **何人でも書ける**：管理者と書き手の2つの役割。招待リンクで参加し、書き手は自分の記事だけを直せる（画面だけでなくサーバーでも確かめる）
- **公開した瞬間に反映**：ページはCDNに長く置き、記事が変わったときだけ消す
- **大きな動画もそのまま**：ブラウザからストレージへ直接アップロード（100MBまで）
- **文書サイトとしても使える**：カテゴリ（棚）・親の記事（章立て）・並び順、パンくずと前後の記事、サイト内検索
- **読む人を限定できる**：記事ごと、またはサイト全体を「ログインしたメンバーだけ」にできる。閲覧専用のアカウントもある
- **文書向けの記法**：脚注、数式（KaTeX）、コードの色分け、PDF・Word・Excel などの添付ファイル
- **持ち出せる**：記事ごとに Markdown・HTML（単体で開けて、動く部品もそのまま動く）、サイト全体を JSON で書き出せる
- **複数のメディアを出せる**：1つの Tsuzuri から「まちのたより」「くらしノート」のように名前のちがうメディアを出せる。メディアごとに名前・ロゴ・読める人を設定でき、トップ・カテゴリ・検索・RSS もメディアごとに分かれる
- **メディアごとに装飾を変えられる**：6つのひな形（標準／ポップ／マガジン／ナチュラル／シンプル／テック）から始めて、好きな色・見出しと本文の書体（約15種）・文字の大きさ・本文の幅・角の丸さ・大見出しと小見出しの形・上のバー・記事一覧の並べ方・背景・リンク・ロゴ画像・表紙の画像・フッターの一文を選べる。設定中は見本がその場で変わる。さらに追加のCSSも書ける。好きな色は、明るい画面・暗い画面の両方で読める濃さに自動で調整する
- **小さい**：フレームワークなし、依存は `@vercel/blob` と `@vercel/functions` だけ

## WordPress とのちがい

**書くことと、動く文書を出すことに絞って、操作と保守を最小にしたのが Tsuzuri です。** WordPress は何でもできる代わりに、そのぶん手間がかかります。

| | WordPress | Tsuzuri |
|---|---|---|
| 書くときの操作 | ブロックを1つずつ足し、右のパネルで設定する。画面の切り替えやプラグインの設定画面が多い | ふつうに文章を打ち、行頭の `/` で部品を選ぶだけ。ボタンは「下書き保存」と「公開する」の2つ |
| 記事の中で動く部品 | クイズ・計算機・グラフなどは、プラグインを探して入れ、互換性を気にしながら更新し続ける | クイズ・計算（スライダーつき）・グラフ・手順・タブ・画像の比較・用語の吹き出しが最初から入っている |
| 保守 | 本体・テーマ・プラグインの更新、PHP とデータベースの管理、バックアップとセキュリティ対策が要る | 更新するものがない。サーバーは Vercel が面倒を見て、保存した版はすべて自動で残る |
| 原稿の形 | ブロックは HTML とコメントの塊で、ほかのツールへ移しにくい | 読める文字の原稿（Markdown を拡張したもの）。Markdown・HTML・JSON でいつでも持ち出せる |
| 速さと反映 | キャッシュ用のプラグインを入れて調整する | 記事はサーバーで完成したHTMLにして CDN に置き、変更した瞬間に入れ替える |
| 文書サイトとして | 章立て・脚注・数式・添付・メンバー限定は、テーマとプラグインの組み合わせで作る | カテゴリ・章立て・パンくず・前後の記事・検索・脚注・数式・添付・メンバー限定が標準で入っている |
| 同時に書く | 同じ記事を2人で開くと、あとの保存が上書きする（編集ロックで防ぐ） | 記事ごとに版を数え、ぶつかったら「最新を開く」か「自分の変更で上書き」を選べる。別々の記事なら同時に保存しても両方残る |

WordPress の方が向いているもの：

- テーマやプラグインで、見た目や機能を大きく変えたいとき
- コメント欄・ネットショップ・多言語のサイトを作りたいとき
- 情報の多さや、仕事を頼める人の多さが大事なとき
- 画面を見たまま組み立てるように編集したいとき（Tsuzuri は「原稿＋読者に見える形」を並べて書く）

## 構成

| 場所 | 中身 |
|---|---|
| `public/assets/render.js` | 記法 → HTML の変換。サーバーと編集画面のプレビューで共用 |
| `public/assets/live.js` | 読者のページで動く部分（クイズ・計算・グラフなど） |
| `public/assets/write.js` / `public/write.html` | 書く人の画面 |
| `public/assets/style.css` | 見た目（黒・白・青、ダークモード対応） |
| `api/index.js` | サーバー。すべてのURLがここに来て振り分ける |
| `lib/pages.js` | 読者のページ・サイトマップ・RSS を組み立てる |
| `lib/store.js` | 記事・アカウント・画像の置き場所（本番は Vercel Blob、手元は `data/`）。保存は通し番号つきの新しいファイルを足す方式で、同時保存でも変更が消えない |
| `lib/auth.js` | アカウント・パスワード（scrypt）・招待・ログイン状態（署名つきクッキー） |
| `content/seed.json` | 最初の記事（まだ何も保存されていないときだけ使う） |
| `artifact/` | Claude のアーティファクトとして動いていた旧版 |

## 自分のサイトとして立ち上げる（Vercel）

1. このリポジトリを fork して、Vercel で新しいプロジェクトとして読み込む
2. Vercel の Storage から **Blob ストア（Public）** を作り、プロジェクトにつなぐ（`BLOB_READ_WRITE_TOKEN` が自動で入る）
3. 環境変数を2つ入れる
   - `TSUZURI_PASSWORD`：最初の管理者を作るときだけ使う、サイトの合言葉（長めのものを）
   - `TSUZURI_SECRET`：ログインの署名鍵と、データの置き場所の鍵（`openssl rand -base64 32` などで作ったランダムな文字列。あとから変えるとデータが見えなくなる）
4. デプロイして `/write` を開き、合言葉と自分の名前・ログインID・パスワードを入れて管理者を作る
5. ほかの人は「メンバー」から招待リンクを作って渡す。最初はサンプル記事が入っているので、書き換えるか削除する

## 本番（Vercel）

- GitHub の main に push すると、Vercel が自動で本番に反映する
- 環境変数：`TSUZURI_PASSWORD`（最初の管理者を作るときの合言葉）、`TSUZURI_SECRET`（署名鍵・置き場所の鍵）、`BLOB_READ_WRITE_TOKEN`（Blob ストアをつなぐと自動で入る）
- 任意：`SITE_URL`（canonical・サイトマップ・OGP に使うURLを独自ドメインに固定する）
- 独自ドメインの追加：`npx vercel@latest domains add <ドメイン>` → 表示される DNS を設定する

## 記法（行頭の `/` で選べば、覚えなくても入る）

| 書き方 | 意味 |
|---|---|
| `## 見出し` | 見出し |
| `**太字**` `==マーカー==` `[文字](URL)` | 太字・マーカー・リンク |
| `[[記事のタイトル]]` | ほかの記事へのリンク |
| `{用語|説明}` | 押すと説明が出る言葉 |
| `文[^1]` と `[^1]: 注の中身` | 脚注 |
| `$a^2$`、`$$ … $$` | 数式（文中・独立） |
| ` ```js ` 〜 ` ``` ` | コード（言語名で色分け） |
| `[資料.pdf](URL)` だけの行 | 添付ファイルのカード |
| `:::quiz` `:::calc` `:::chart` `:::tabs` `:::steps` `:::details` `:::compare` | 動く部品 |

## 原稿の先頭で切り替える

原稿のいちばん上に `---` で挟んで書くと、その記事のメディアやデザインを Markdown のまま切り替えられます（行頭の `/` から「記事の設定」を選ぶと入ります）。

```
---
メディア: まちのたより
デザイン: ポップ
色: 緑
カテゴリ: カフェ
---
本文……
```

| 書ける項目 | 書き方の例 |
|---|---|
| メディア（media） | メディアの名前か URL（`くらしノート`、`kurashi`） |
| デザイン（theme） | 標準・ポップ・マガジン・ナチュラル・シンプル・テック。`メディアと同じ` ならメディアの設定に従う |
| 色（color） | 青・赤・緑・橙・紫・青緑・黒 |
| カテゴリ・親の記事・並び順 | `カテゴリ: マニュアル`、`親の記事: 使い方ガイド`、`並び順: 2` |
| 読める人 | `誰でも` か `メンバー` |
| 日付・URL | `日付: 2026-10-11`、`URL: cafe-tour` |

デザインと色はその記事のページにだけ効き、メディアのトップはメディアの設定のままです。原稿の先頭と「記事の設定」の欄の両方に書いた場合は、原稿の先頭が優先されます。

## できないこと

- メンバー限定の記事に入れた画像・添付ファイルは、URLを知っていれば誰でも開ける（URLは推測できない長さにしてある）
- アップロードは100MBまで。長い動画は YouTube に上げて、URLを1行で貼る
- メールは送らない。招待リンクとパスワード再設定リンクは管理者の画面に出るので、それを本人に渡す
- 画面とメッセージは日本語のみ
